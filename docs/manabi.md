# 866枚を作り直して分かったこと（型と決まり）

867ページのセミナー資料を手本にして、全ページを Google スライドに作り直した記録から、
次に同じ物を作る人（AI）が守ること・やってはいけないことだけを抜き出したものです。
進め方はいつも「仮説 → 試し → 数字 → 結論（当たり／外れ）」です。

## 結果の数字

- 作り直し 866 枚・作れなかった 0 枚（1枚は手本の画像が壊れていて、取り直した画像で作った）
- 合格の線：違う所（ratio）3% 以下 かつ ssim 0.985 以上（800×450 で比べる）
- 最後に並びを確かめた：作った資料の順が手本の順と一致（重複 0・抜け 0）・ランダム10枚が全部合格（ratio 最大 1.27%・ssim 最小 0.9884）
- 型：1ページ＝1型でまとめずに 867 型。そのうち新しい文で使えるのは 770 型（作り直し合格・写真や画面の切り抜き・動画なし）
- 一言の頼みから10枚を作る試し：1回目は門の不合格1枚＋目で見つけた不具合3件 → 直して2回目は 0 件

## 型の分け方

- 大きな型（見た目の骨組み）10 種＋その他：
  A 見出し帯＋本文（STEP帯）／B 人物＋問いの吹き出し／C 中央の一言＋下に人物／D 色帯の強調／E 大きな数字・言葉の強調／
  F カードを横に並べる（2〜6枚）／G 流れ（五角形の矢印・番号つき箱）／H 画面差し込み／I キャラクター＋吹き出し／J 昔／今 の対比
- 伝えたいこと 15 種（1つの型に複数付く）：
  問いかけて考えさせる／数字で驚かせる／比べて差を見せる／手順を見せる／全体を一覧で見せる／不安をあおる／
  悩みを代弁して共感させる／結論を言い切る／実績で信じさせる／未来を見せて期待を上げる／特典・行動を促す／
  章を区切る／キャラに語らせて親しみを出す／人物の表情で気持ちを見せる／説明する
  （文言と形の決まりで自動で付けた。推測を含む）
- 連番の組（同じ絵に1つずつ足していく）70 組・225 枚／似せて続ける組（同じ形で文言だけ替える）95 組
- 新しい台本を並べるとき：前の2〜3枚と同じ大きな型を置かない・同じ型は使い回さない。800 枚の試しで、手本の並び（同じ大きな型が最長33枚続く）→ 最長3枚に下がった

## 作り直しで当たった決まり（道具に入っている）

1. 絵の焼き込み：塗りの範囲（fillRect）が負の値の画像を飛ばしていた → 貼り付けで焼く。枠の線は太さの半分＋0.5pt 外へ広げて描く。違う所 11.9%→2.4% など
2. 文字の縦位置：手本は最後の行の行間の伸び（大きさ×1.2×(行間−100%)）を数えない。下寄せは全部・中央寄せは半分・上寄せは伸びが 4pt 以上なら 0.45pt 下げる。同じ10枚で平均 1.85%→0.74%
3. 文字の左右：余白を広げた箱だけ、左揃えは 0.45pt 右・右揃えは 0.45pt 左。同じ10枚で平均 0.64%→0.45%・悪くなったページ 0
4. 箇条書きの記号：Slides の型（●）を使わず、手本の記号「•」を文字で入れる。字下げの頭を記号の幅（0.35em）だけ左へずらし、記号＋すき間（en スペース 0.7倍）を置く。違う所 4.17%→0.08%
5. 人物の大きさ：手本の枠の高さに合わせる（横幅に合わせると縮んでつぶれる）。高さ 56%→100%
6. 1行の箱に2行を入れない：アイコンと文字の重なりの主因はこれだった（余白ではない）。文字数の門で止める → 重なり 0
7. 箱の上限（1行の字数・行数）は「実際に置ける幅（枠の線・横の絵の手前まで）」で数える。手本の1行より厳しくはしない。半角は 0.5 字
8. 手本の1語の下に敷いた目印の板は、文を入れ替えたら外す（770 型で 27 層・12 ページ）
9. 人物の差し替えは「スーツの1人の人物」の絵だけ。ロゴ・キャラクター・何人かの絵・物は差し替えない
10. 強調色は地と違う色（紺地なら黄）。箱が足りないときは下へ伸ばしてから字を小さく

## 外れた仮説（入れていない）

- 行の送り（行間）を手本との比で広げる：送りが手本を越えて悪化（4.06%→4.84%）。行間の％と送りは比例していない
- 残る差の1〜2.5% はページ全体の位置ずれ：全体をずらしても最良は 0,0。全体のずれではなかった

## 事故から決めたこと

- 作り直し（build）は同時に1本だけ。周回の最中に試しを走らせ、試しの後始末が周回の一時公開を外した → 鍵を入れた
- 周回は kill せず止めの札で止める（kill すると素材の一時公開が残る）
- 仮のページの名前は毎回変える（前の回の残りで作れなくなる）
- 読めない JPEG は macOS の sips で PNG に直して使う
- 待ちのループの pgrep は自分を拾う → `pgrep -f "[p]ython3 .*zenbu"` の形で書く
- 試しには文字の多いページを選ぶ（絵だけのページはほぼ必ず通り、試しにならない）
- URL を渡す前に、手本の同じ型と左右に並べた画像を必ず目で見る（門が見逃した物を目で3件見つけたことがある）
- 渡す前に資料の枚数を API で数え、台本の枚数と合っているかを確かめる

## 残っている差（次の仮説の候補）

1. 小さい字が多いページ：字の縁のにじみ（最大 2.98%）
2. 回転した物：違う所は小さいが色の差が少し残る
3. 行の送り：作り直しの送りが手本より約1.2%短いページがある。字の大きさ・行間％・送りを全ページで集めて、どこで食い違うかを数えてから決める
